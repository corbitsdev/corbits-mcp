Snapshot: 2026-10-25. This matrix records implemented scope, assertion locators
and qualified evidence, not a blanket MCP compliance verdict. The integration
gate passed final QA with 423 tests and 2,116 assertions; qualified build, e2e
and package evidence is recorded separately in integration-status.md. Counts do not prove every
normative clause or deployment. No stale missing-export or mandatory-OAuth
blocker applies to the current package.

## Implemented compatibility and review scope

The server implements opt-in 2025-11-25/06-18/03-26 Streamable HTTP sessions;
modern remains stateless. See [legacy deployment and limits](legacy-server.md).
Legacy now has final scoped approval: 50 tests / 319 assertions plus 5
independent tests / 63 assertions, as reported by the director. Both header and
shutdown repairs are closed. This is separate from the approved core F1–F11
repairs and does not substitute for final reconciled QA. No removed HTTP+SSE or resumption support is claimed.

Apps advertisement requires explicit host bridge support, sandbox renderer,
CSP enforcement, authenticated bridge and presentation. Metadata-only handling
never advertises Apps. The host still supplies the actual renderer and enforces
its security properties; the library's gate is not a deployed-browser audit.
Skills verification supports bounded 16 MiB decoded resources; independent
review exercised actual authenticated loopback and all bounds. Verification is
not approval to admit context or execute code.

The verified Skills adapter declines dynamic manifests, as permitted by the
pinned specification. It requires complete resource reads with exactly one
matching text/blob item; resource-read MRTR is unsupported by that adapter.
These are explicit supported-shape limits, not a reopening of the approved
resource bounds or a claim that dynamic consumption is mandatory.

## Remaining actual requirements

- **CL11479 — external OAuth-core defects:** stock 0.3.0 token/profile/storage
  requires refresh tokens; stock token POST follows redirects and exposes raw
  response errors; authorize extras can overwrite state/PKCE. Guarded MCP
  sessions avoid those paths but do not fix stock OAuth-core. Stock hub DCR-only
  selection and present-but-unadvertised issuer handling are additional documented
  integration limits, not silently added issue acceptance criteria. Resource
  exchange/refresh propagation already exists upstream; the local config omission
  was fixed. See [guarded auth and companion limits](public-api.md).
- **CL11480 — external credential-http defects:** old harness/types peer ranges
  block the pinned full hub install; Request+init semantics and insecure configured
  destination schemes also need upstream correction. Neutral installs pass and
  must not be conflated with this optional host failure.
- **Host obligations:** trusted identity/grants, cryptographic verification or
  introspection, credential storage, callback/registration setup, explicit selected
  bindings, durable recoverable executors, session affinity, skill approval and
  context lifecycle, and Apps renderer/bridge security. These are injected
  application responsibilities, not invented missing library features.
- **Unverified deployments/clauses:** production DB transactions, live OAuth
  services and callback deployment, distributed lifecycle durability, browser
  sandbox enforcement, and exhaustive revision-by-clause coverage require their
  own evidence. No 100% conformance or production certification is asserted.
